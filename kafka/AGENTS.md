# KAFKA 固有実装ルール

このディレクトリは downstream 独自コードの所有領域。

- 通常作業のbranchは `master`。
- `kafka` branch は旧名互換であり、正本ではない。
- `upstream` branch は自動同期専用。
- 全 `*.md` は upstream 同期対象外。
- 新機能は adapter / wrapper / config / dependency injection を優先する。
- upstream core を直接改変して恒久patchを抱えない。
- DB schema は複製せず canonical persistence API を使う。
- silent fallback を作らない。
- upstream API / schema 変更で互換性が壊れたら fail loudly / UNVERIFIED。
- risk guard は LLM から独立した deterministic layer とする。
- paper/testnet を実売買より先に検証する。


## HFT 自律研究の対象範囲（2026-11-12）

本プロジェクトの定期自己改善は、現在利用可能なGitHub、公開・無償・利用条件を確認できるデータ、手元で実行できるコードとテストのみで**最後まで検証できる作業**を対象とする。ブロックされた外部依存を毎時追い続ける運用は廃止する。

- **対象**: データの型・単位・ID・欠損・重複・来歴の検証、明示的な時刻単位変換、合成fixtureを使ったオフライン再生とテスト、取得・保存が許可された公開履歴データに対する検証、手数料・遅延・jitter・スリッページ・約定モデルの仮定を明示したシナリオ比較、既存コードの再現可能な修正。
- **対象外**: 本番VPSや私有ログの取得、口座情報・鍵・秘密値の投入、発注・実取引・本番デプロイ、実環境の時計同期・実測ネットワーク遅延、個人の約定履歴・適用手数料、有償・権限未確認データ、収益の実証。これは待機タスクではなく `OUT_OF_SCOPE` と記録する。該当データを毎回要求しない。
- 合成データの成果は `CODE_VERIFIED`、公開市場データに基づく成果は入力と検証期間を固定したうえで `PUBLIC_DATA_VERIFIED` 等と区別する。実売買の収益・実行遅延・実際の約定を証明したことにしない。
- 毎回、既存の実験記録・直前の差分を読んでから、**今ある入力で検証を完了できる最小の一件**を選ぶ。新しいIssue/実験ID/CIを増やさず、既存の実験記録に追記し、意味のある変更だけをコミットする。
- 実行可能な独立改善が尽きた場合は `FIXED_POINT` とし、未解決の外部要件を言い換えた報告や無意味なコミットを繰り返さない。
